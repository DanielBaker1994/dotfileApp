# G2 - prose inline vs pop-out (2026-10-20)

Setup: sandbox HOME=/private/tmp/kssb/home, notes in home/notes (created before launch, so the sidebar was empty until "+"
made Untitled-1.md; test content was then copied over Untitled-1/2.md on disk and the editor reloaded). Inline prose toggled with the
"Prose" capsule button; pop-out with the capsule's last icon (Cmd+Shift+O also exists, host.rs:5976). Shots: shots/G2-*.png.
Fixtures: notes/{img1,dia,tbl,broken}.md + abs.png, img/local.png.

## F1 - S2 - 5/5 (every open, relative AND absolute path) - pop-out shows alt text instead of the image (HEADLINE)
Steps: note with `![rel](img/local.png)` and `![abs](/private/tmp/kssb/home/notes/abs.png)`; Prose button -> both images render
(shots/G2-img-inline.png); click pop-out icon -> child `kitchen-sink prose ... Untitled-1.md` window shows only the alt text "rel" / "abs"
in a tiny bordered box (shots/G2-img-popout.png). Same on all 5 reopen cycles. Not the PDF: the exported PDF for the same note contains
2 /Image objects, and the editor draws them too.
Hypothesis (high confidence): inline writes the page to a temp file and loads it with `loadFileURL_allowingReadAccessToURL(url, "/")`
(notes_prose.rs:377-379) so `file://` images are readable. The pop-out loads the same HTML with
`loadHTMLString_baseURL(html, None)` (notes.rs:3061-3062, called from ProseWindow::show at notes.rs:3160): the page origin is
about:blank and WebKit blocks file:// subresources, so the `<base href="file://...">` (notes.rs:1227/1297) is useless. Fix: write the html to
a file and use loadFileURL with read access "/" like notes_prose.rs, or pass a file:// baseURL and a read-access grant.
Also the same loader means the pop-out cannot show any other local file resource.

- H1 (child dies when menu closes / unscoped will-close): NOT reproduced. Child pid stayed alive after 4 menu opens, 2 picks, Esc-less dismissal;

- H3 (EXPORTING latch stuck): NOT reproduced. Copy PDF Path in the pop-out worked 2/2 in a fresh child and again in a later child: clipboard =

- H4 (helper fails in child): falsified, same evidence. Copy Absolute Path also OK (clipboard = note path).
Inline right-click menu: same two rows, Copy PDF Path OK (clipboard Untitled-2.pdf).
So the owner's "right-click PDF in pop-out" symptom did not reproduce here after the 2026-10-17 fixes (note: sandbox runs the repo app; owner's installed binary
may predate them). Minor: the menu rows render white-on-translucent-grey, low contrast on a white page (S4).
