# H2 — notes/files ops vs disk truth (headless sandbox, 2026-10-20)

Sandbox: `.build/mcp-sandbox-hl` (headless daemon, socket `tmp/ws-notes.sock`, `WS_HOME`/`HOME` = sandbox `home/`).
Notes folder: `home/notes` (from `[notes] paths = "~/notes"`). Live app not touched. No GUI, no screenshots, no source edits, no build.

## Coverage gap (the main result)

The headless socket does not expose notes file operations. Checked the verb table in `rust/ws-rs/src/app/host.rs`
(`do_host_action`, ~L1771-2030) and `views/notes.rs` (`register`, ~L5680):

- Notes-side `do:` verbs that exist: `open:notes` / `show:notes` (view open), `rail:notes`, `sidebar-width:notes`,
  `esc-hides:notes`, `header-style`, `key:<spec>` (record-only), `focus:`/`pane:`. Plus the test table entry `notes:state`,
  which returns only `{"available": true}`.
- Not present (all return `{"error":"unknown action notes:<verb>"}`): `notes:new`, `notes:rename`, `notes:list`,
  `notes:tree`, `notes:search`, `notes:delete`, `notes:move`, template/snippet/completion/prose verbs.
- Window-only verbs are refused headless by `needs_window()` (`notes-find`, `notes-grep`, `paths:show`, `tool:*`).

So rename/delete/create/search/move cannot be driven or checked over the socket. Those need the GUI, which H2 is not allowed to use.

## Findings

**H2-01 · S4 (observability, probably by design) · repeat 3/3**
- Steps: `do:open:notes`, wait 3 s, `state` → `views.notes`.
- Disk: `home/notes` holds 14 entries (unicode, emoji, dot-leading, 200-char name, 5000-line note, dup folders).
- Expected (for an automation oracle): `rowCount` / `tabs` / `selection` reflect the notes folder.
- Actual: `rowCount: 0`, `tabs: []`, `sidebarCursor: 0`, `selectedTab: 0` always. These are literal placeholders in
  `rust/ws-rs/src/app/host.rs` ~L536-548 (the "Swift keys" block). `notes` top-level state is `null`.
- Impact: no socket oracle exists for notes content. The lane's disk-vs-state comparison was impossible.
- Likely source: `rust/ws-rs/src/app/host.rs` ~L536-548; `views/notes.rs` `test_state` (~L5650) is not reached in headless.

**H2-02 · S4 · repeat 3/3**
- `do:notes:<new|rename|list|tree|search>` return `unknown action`. The verbs are simply absent, so no ops could run.
  Consistent with H2-01. Source: `rust/ws-rs/src/views/notes.rs` `register` (~L5680).

## Run performed

- 150 socket ops in one script (`scratchpad/run.py`), mixed `do:open:{notes,files,jira,confluence,compare,config,detail}`,
  `do:key:cmd+n/cmd+o/esc`, unknown-verb probes, and 30 disk churn steps in `home/notes`
  (create/remove of `ünï ✓ 🚀.md`, `sp  ace.md`, `.hid.md`, a 200-char name, `a.b.c.md`, a tab in the name, and `dup.md`).
- After every op: pid alive, `state` parses as JSON, no transport exception.
- Every 10 ops: sha256 of all pre-existing fixtures compared to baseline (app must not rewrite them);
  `daemon.log` checked for `panicked` / `already borrowed`.
- Result: 150/150 ops answered, 0 invariant failures, 0 fixture mutations, 0 panics or borrow errors in the log.
  Error replies were only the expected unknown-verb ones (`notes:new`, `notes:rename`, `bogus`).
- Fixtures: created by `scratchpad/mkfix.py` inside the sandbox `home/notes` only.
- Not covered (no socket surface): note content ops, the 5000-line / code-fence / table / image / diagram rendering
  checks, duplicate-name rename/move behaviour, search/finder, templates/snippets, completion state, prose pop-out.
  These need the GUI lanes (G1-G3) or a unit test, not this lane.
- Not checked: `cargo test` for notes model (out of lane; no build allowed).

## Real app bugs found in notes/files ops: none observed (in the headless surface).
