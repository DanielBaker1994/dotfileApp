# H1 — headless state-transition soak (2026-10-20)

Lane: headless sandbox (`.build/mcp-sandbox-hl`), socket-only, no GUI, no screenshots, no source edits,
no `./ws build`, no kill/restart, `ai` view never opened.

## Coverage
- 3 seeded random walks x 320 steps = **960 steps** (seeds 101, 202, 303), run sequentially on the one daemon.
- 57 distinct `do:` verbs exercised: open/show for notes, files, jira, detail, releases, config, output,
  confluence, compare, compareText; hide, back, home, toggle, cycle, cycle-back, show, switcher, switcher-hide;
  paths:show/hide/return/select:N; tool:/tool-close: (prettyprint, paths); toggle-terminal, toggle-browser,
  term, notes-find, notes-grep, jira-jump, jira-dashboard, jira-config, reset-size; rail:<view>:toggle/on/off;
  pane:h/j/k/l/focus:x; esc-hides:VIEW:on|off; hide-on-focus-loss:on|off; compare:back.
- Invariants checked after every step: `state` answers within 3 s and parses; at most one view has
  `shown: true`; `view` is non-empty iff `visible`; the current view is shown; no `panicked` /
  `already borrowed` / `ERROR` lines appended to daemon.log; no unexpected error reply to a `do:` verb.
- Action-specific checks: open/show:V must yield `view == V` and `views.V.shown`; hide must clear
  view/visible; toggle must flip visibility; cycle/cycle-back/home/show must keep a visible view visible;
  tool-close:X must clear `tools.X.shown`.
- Headless-refused verbs (`needs_window` in host.rs) were accepted as expected "unavailable in headless mode".

## Findings
**No violations in 960 steps.** No crash, hang, panic, RefCell borrow message, or ERROR line; the daemon
answered `state` on every step.

## Observed once, not reproduced (S3, unconfirmed)
- **H1-obs-1 · S3 · repeat 1/4 (not reproduced in 3 retries)**
  - Trail (seed 99 smoke run, the first open of confluence in this daemon's lifetime): `switcher-hide`, `show`
    (landed on jira), `open:compare`, `rail:notes:on`, `open:confluence`.
  - Expected: `view == confluence` (the `present()` in `host.rs` sets `current` unconditionally).
  - Actual: `view == jira` right after the `open:confluence` reply.
  - Retries of the same sequence (x3) and a bisect over the same tail all showed `confluence`.
    The 320-step walks reopened confluence 55 times with no mismatch. The only difference seen was that
    the failing run was the first confluence open in that daemon. Cannot re-test without a daemon restart,
    which is not allowed in this lane.
  - Likely source: `rust/ws-rs/src/app/host.rs` (`present`, `open`, `UiCommand::Present` handling on the
    daemon UI side), or a lazy confluence build that re-targets `current` to jira on first presentation.

## Coverage gaps (what this lane cannot see)
- `focused` is always empty headless, so the one-focused-view invariant is only checked in its
  "shown" form. Focus behaviour needs the GUI lanes.
- Headless refuses `tool:*`, `paths:show`, `switcher`, `term`, `toggle-terminal`, `toggle-browser`,
  `notes-find`/`notes-grep`, `jira-jump`, `reset-size`, `board:*`. Their state transitions are not exercised here.
- `pane:*` is a no-op without a window, and `rail:*`/`esc-hides`/`hide-on-focus-loss` only change in-memory
  state, not rendering.
- Minimisation was not needed (no finding reached the repro stage).
