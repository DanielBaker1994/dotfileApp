# Plan: data out of code — JSON homes for shipped defaults, tables and word lists

Owner mandate: **code is behaviour, JSON is data.** Any value a user could
want to read, change or override — defaults, command/template strings (what
actually runs), name/symbol/key tables, word lists, window/limit numbers,
layer/label lists, presets — lives in a JSON file the code loads at import,
never as a literal in `.py`. This plan is the working record; no GitHub
issue (same as the sibling plans).

The established pattern (verify, then follow):

- JSON sits beside its module/package: `settings_hub/data/tables.json`,
  `jira/defaults.json`, `confluence/defaults.json`, `notify/defaults.json`,
  `pylib/paths.json`.
- The module loads it at import with `os.path.dirname(os.path.abspath(__file__))`
  and keeps the **old Python symbol names** so callers (and the Swift helper
  protocol) don't churn.
- User config (`commands.toml`, `~/.config/*/config.json`) overrides the
  shipped JSON; JSON is the discoverable truth of "what happens by default".
- One home per table: a table in JSON is never copied back into code.

## The rule, tightened

**DATA → JSON** when the value is one of:

1. a config default (the value used when the user's config is silent);
2. a command / JQL / template string that actually runs, or a CSS/Lua/markdown
   default template;
3. a name / symbol / key / label table (tools, chords, fields, layers,
   categories, "why" vocabularies);
4. a word list (status words, filler words, skip lists);
5. a window / limit / retry / cap number;
6. a preset list (themes, doc templates, buttons).

**MECHANISM → stays code**: parsing regexes; control flow; name→function
dispatch tables (`READERS`, `METHODS`); grammar vocabularies that are parsed *as
syntax* rather than chosen as content (`tri()` words, TOML escape table); a
value generated by an algorithm (xterm cube, colour algebra, geometry, ring
layout maths, path derivation).

**WIRE-FORMAT → stays code** (a narrow mechanism case worth its own name):
values that are persisted or sent across the process boundary in a shape
somebody else parses (status `TIME_FMT`, compare `ROWS_*`/`OP_*` codes, EOL
byte codes, TUI escape-sequence tables). Changing these silently breaks
stored data or a peer; they are contracts, not preferences. The *labels* for
those codes can be data (see EOL_LABEL).

**PRESENTATION copy → stays code** unless a config key can override it:
page HTML/CSS skeletons, dashboard/status/setup summary sentences, toast
strings in Swift that are not (yet) config defaults. Extract only when a
user-facing override story exists; otherwise JSON buys escaping pain and no
transparency. (Swift config toasts that *are* `[screenshot]` defaults are
listed in the Swift section — those are defaults, not copy.)

**TEST FIXTURE → out of scope**: `Tests/**`, `jira/fake_jira*.py`,
`confluence/fake_confluence.py`, `bin/ui-test-focus.py`. Tests are not
shipped defaults; their literals are allowed to stay and are the guard, not
the subject.

**LAYERING** stays transparent: `commands.toml` / user config wins over the
JSON; JSON wins over nothing (no third copy in code).

## Risk notes

1. **Import-time reads hard-fail.** Every new load follows `jira_fields.py`
   (`with open(...)` at import); a missing JSON kills the helper worker and
   the app falls back to Swift mirrors (e.g. `ShotTool.ring` returns `[]`).
   The JSON must be committed in the same commit as the loader switch.
2. **Deployment OK by construction.** `install.conf` `RESOURCE_LINK_DIRS="bin
   jira confluence notify vim pylib settings_hub"` and `build-app.sh`
   `bundle_resources` copies with `git ls-files -co --exclude-standard` — a
   JSON beside the module ships to `Resources/<dir>/`, so `__file__`-relative
   paths resolve in the bundle exactly as in the repo. `.gitignore` has no
   `*.json` exclusion (only `settings-hub.json`, a user data file). No
   installer/DMG change needed.
3. **Never read JSON relative to cwd.** Tests run from `Tests/`; the helper
   may run from anywhere. Use `os.path.dirname(os.path.abspath(__file__))`.
   For pylib→jira cross-reads keep the `../jira/defaults.json` layout
   (both dirs are copied side by side).
4. **Late-configured PythonHelper.** `Tests/test_helper.py` and
   `test_python_helper.swift` spawn the real worker with temp envs; no new
   module-level read may depend on `WS_*`/home. Keep env-dependent paths
   (`jira_paths`, notify cache) as code.
5. **Byte equality where compared.** `SOURCEPOS_FILTER` is compared to the
   cached file text; JSON round-trip must preserve it exactly (verify with
   `./ws test prose-pdf`, which exercises the filter path).
6. **Values asserted by tests.** `test_ansi.py` (palette/theme colours),
   `test_jira_data.py` (words), `test_shot_model.py` (ring order), `test_paneshot.py`
   (defaults) assert through symbols; keep values byte-identical and the
   tests stay green without edits.
7. **Swift mirrors keep drifting until their batches.** Moving the Python
   copy to JSON does not update `ShotTool`, `AnsiTheme`, `ScreenshotConfig`/
   `PaneShotConfig`, `ThemePreset.builtIn`, `JiraTicket.categoryNames`. The
   JSON becomes the reference those batches read from; until then, edits to
   the JSON alone won't change app behaviour on those paths (they already go
   through the helper for ring/args — tooltips/icons are still Swift).
8. **Borderline refusals are deliberate.** `MAX_WORKERS` (helper pool),
   `stack_new(limit=50)`, `TIME_FMT`, EOL byte codes, `tri()` words, page
   HTML/CSS skeletons and dashboard/setup copy stay code — see rule section.
   If the owner overrules one, it is a one-file change in its batch.
9. **PATH bootstrap duplication** (`script_bridge.DEFAULT_PATH`,
   `status.py`, `config_text.resolve_binary`) is mechanism; if it ever
   matters, consolidate to one constant (no JSON), not part of these batches.
10. **`DEFAULT_STATE_PATH` mismatch** (`screenshot.json` vs the app's
    `screenshot-state.json`): ~~is a real latent bug found during this audit;~~
    → hygiene only, **not a live bug** — the helper (`pylib/helper/methods.py`
    `shot.state_load/save` passes `params.get("path") or ""`) and Swift
    (`ScreenshotAnnotations.swift:1057/1067`, path built in `Screenshot.swift:411`)
    always pass a path, and `state_load("")` silently returns `{}`.
    P1 may align the constant with the app, but must **not** make `state_load("")`
    fall back to it (that would change behaviour for empty-path callers).
11. **Half-moved cache paths.** Moving `ME_FILE` alone would put cache-file
    names in two homes (`pylib/paths.json` + literals). Resolve the added
    "cache-file names" row in Inventory B first (sweep all in J5/J6, or drop
    `ME_FILE`).
12. **S1 has no test pin.** `Tests/test_settings_hub.py` never references
    `MOD_ORDER`/`MOD_SYM`/`LAYER_NAME`, and `LAYER_NAME(app="app")` ≠
    `LAYER_TITLE(app="kitchen-sink")` is unresolved drift. Decide intent and
    add a pinning assertion before collapsing, or S1 can silently relabel the
    picker.
