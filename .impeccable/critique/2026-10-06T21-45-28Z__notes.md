## Design Specificity Verdict

**Partly grounded — the container is unmistakably kitchen-sink; the editor body is category-interchangeable.**

**LLM assessment.** The container is authored: notes is a `SlotMember` of the one shared window (`SharedWindow.swift:44`), same `slotBaseFrame`, no view switch resizes it, 30 pt crust header with no title, `stretchHeaderButtons = false` in shared mode. The keyboard plumbing is product-specific (Ctrl+B prefix, Ctrl+H/J/K/L panes, Cmd+\ rail, dictation landing at the cursor via vim extmarks or `replaceRange`, commands.toml openable as a note with live validation). The `[notes] paths` list is an idiosyncratic "everything bucket" (notes, but also `commands.toml`, `curl.log`, `config.json`). But strip the alternate modes and what remains is a plain `NSTextView` (`buildEditor`, `PopupWindow.swift:8977`) whose `restyleEditor()` (`:9939`) applies one uniform font+color to the whole buffer — headings, bold, lists, links show as raw `#`, `**`, `-`. Only `![…](…)` is special-cased. The characterful parts (nvim, Prose) are alternates, not the default surface.

**Deterministic scan.** The detector is HTML/CSS/DOM-based and found **zero** findings in `kitchen_sink.swift` (exit 0, empty array). Over the repo root it exited 2 with 108 findings — all in checked-in generated docs (`README.html` 54, `PRD-screenshot.html` 54; `design-system-color`, `design-system-font`, `low-contrast`, `tight-leading`, `em-dash-overuse`), **0 in any `.swift` file**. ## Overall Impression

A powerful, deeply keyboard-integrated notes surface built on a genuinely strong data model, dragged down by three things: it is the hardest surface in the app to summon, its one destructive action is silent, and its default editor is the least designed part of an otherwise meticulous visual system. Biggest opportunity: make the editor itself carry the "terminal card" identity the rest of the window already has.

## What's Working

1. **The never-lose / never-resurrect data model.** `commitSave` + `watchTick` + `ensureDefaultNote` (`kitchen_sink.swift:8295`, `:8345`, `:7813`) turn "the file vanished under you" into a graceful tab swap and refuse to recreate deleted files — an entire class of anxiety removed.
2. **Prose mode is genuinely distinctive.** `ProseRender.page` (`NotesProse.swift:212`) builds a real reading surface: serif column, meta line, GitHub alert tones, per-language Nerd-Font badges, task checkboxes, themed selection, pop-out to its own process. A "publish/read" side generic editors lack.
3. **Keyboard depth + config-as-code.** Cmd+/ everywhere, Ctrl+B prefix, Ctrl+H/J/K/L panes, Cmd+\ rail, commands.toml editable as a note with live validation in the status bar.

## Priority Issues

**[P0] Notes is unreachable without a detour.**
- **What:** No global hotkey; `[notes] in-palette = false`; the shared window defaults to `last = .files` (`SharedWindow.swift:201`). Notes opens only via Hyper+S → the last palette entry "Kitchen Sink", or the header icon.
- **Why it matters:** The namesake surface is the least discoverable thing in an app whose promise is "a hotkey away". Every use costs a palette hop.
- **Fix:** Bind a direct hotkey, default the shared window to notes, or add it to the palette.
- **Suggested command:** `onboard` / `shape`.

**[P1] Closing a tab silently rewrites config forever.**
- **What:** `closeNote` (`kitchen_sink.swift:8079`) calls `DismissedNotes.add` + `removeNotePathFromConfig` with no confirmation, toast, or undo.
- **Why it matters:** A stray ✕ permanently removes the note from the app; the file survives but the user's list changes irreversibly — the one destructive action with no guardrail.
- **Fix:** In-window confirm card (`CardWindowController.confirm`) or an undo toast that re-adds the path and clears the dismissal.
- **Suggested command:** `harden` / `clarify`.

**[P1] The notes path violates its own Theme-Only and Contrast-in-Code rules.**
- **What (detector):** Voice meter paints `NSColor.systemRed` / `.white` (`PopupWindow.swift:7760,7786,7793,7798,7805,7811,7818,7833`); the notes mic glyph is tinted `NSColor.systemRed` (`kitchen_sink.swift:2201-2203`) — a direct "Theme-Only Rule" break; it cannot be themed and ignores light presets. `NotesProse.swift:247` draws fenced-code text with `tone(.accent2)` (only 3:1) instead of `ensure(…, on: mantle)`; alert title text (`:178,181`) and the status bar's error text (`PopupWindow.swift:7001`) use `tone()` against a composited tint rather than `ensure(fg, on: over(tint, alpha, on: base))`.
- **Why it matters:** DESIGN.md's own rule says every themed colour must survive all 29 presets including Paper/Latte/Solarized Light. These can fail contrast on light themes.
- **Fix:** Route every notes-path colour through `ensure` / `accentOn` / `onAccent`; replace `systemRed` with `tone(.danger)`.
- **Suggested command:** `polish` / `colorize`.

**[P2] Three rendering models, and prose sub-sizes ignore the user's font.**
- **What:** One file renders raw markdown (native uniform font), styled (vim `render-markdown.nvim`), or serif (Prose). In native mode the markup is unstyled. `NotesProse.swift:204,207,241` hard-codes fence-header `11.5px`, glyph `15px`, meta `11px` — not derived from `[notes] prose-font-size`, while the body is `Int(size)px` (`:236`), so raising the size grows the body but leaves those fixed.
- **Why it matters:** Users can't tell which view is "the" document; the font setting silently under-applies.
- **Fix:** A lightweight native markdown styler (reuse `setEditorSyntaxHighlighted`'s pattern), or make vim/Prose the default presentation; derive all prose sizes from `prose-font-size`.
- **Suggested command:** `typeset` / `polish`.

**[P2] Zero accessibility labels; chrome sizes bypass the Zoom Rule.**
- **What (detector):** Across the entire Swift codebase there is exactly **one** accessibility call (`FilePopup.swift:282`). The custom-drawn notes sidebar (`PopupTabsBar` rows, badges, ✕, +), the `PopupChrome` header, `PopupStatusBar`, and `ProseView` expose no `accessibilityRole`/`Label`/`Value`. Separately, several notes-path sizes skip `* zoom`: status-strip font 10.5 (`PopupWindow.swift:7000`), header meta 9 (`:7544`), meter fonts 11/12 (`:7772,7841`), `meterBarHeight 36` (`:7195`).
- **Why it matters:** VoiceOver gets no meaningful element for the notes tab sidebar or its badges; Cmd+± leaves these labels/controls at a fixed size.
- **Fix:** Add accessibility label/role/value to the custom-drawn sidebar rows, header glyphs and status bar; multiply chrome metrics by `zoom`.
- **Suggested command:** `audit` / `adapt`.

## Persona Red Flags

**Jordan (First-Timer).** `[notes] vim-mode = true` drops a newcomer into a modal nvim with no mode echo or statusline (`vim/init.lua`); `start-drawer = "none"` leaves a blank editor with no empty-state text; the header has no title. First real action, "+" → "Add a note", shows a system alert then demands an absolute path (`presentPathSheet`). The sidebar lists `commands.toml`, `curl.log`, `config.json` as if they were notes. Esc behaves differently by mode.

**Sam (Accessibility).** Dense type (9 pt meta, 10.5 pt buttons, 13–16 pt mono), 1 px hairlines, 26 pt nav icons and a 22 pt add button as targets. State is colour/hover-only: the active tab is a solid accent pill, tab ✕ appears on hover, drawer/mic/mode state lives in menu checkmarks. No accessibility labels on the custom-drawn sidebar/header (detector confirms 1 in the whole codebase). Contrast *is* lifted in code — a genuine plus.

**Alex (Power User).** Notes has no hotkey and isn't in the palette — the opposite of the power-user promise — though once inside it is excellent (vim, panes, drawers, CLI, socket). The ~18-item icon menu and 8-item Notes Settings submenu slow him down.

**Riley (Stress Tester).** A 14-entry `paths` list auto-expands on the 1 s `watchTick`, so the tab set mutates live; `commands.toml` is both a tab and the config being rewritten; closing a tab rewrites config while the watcher may re-add files; voice extmarks + `:wall` autosave race on one buffer; drawers grow by the top edge and clamp at screen height.

## Minor Observations

- **`NSAlert` for add-note** (`addTab()`, `PopupWindow.swift:8183`) directly violates DESIGN.md ("Don't ask with an `NSAlert` … use the confirm card").
- The vertical sidebar marks the selected notes tab with a `surface1` fill and **no accent marker** (`PopupWindow.swift:1867-1869`), while the horizontal strip uses a 2 pt accent underline and DESIGN.md §Tabs specifies a solid accent pill — DESIGN.md not updated for the quiet sidebar.
- `install()` sets `chromeHeaderTitle` twice (`:7877`, `:7888`); `loadTab` re-sets copy-path labels.
- `[notes] width/height/max-height` are largely dead in shared-window mode (the shared window uses `sharedWindowFrame`).
- Clicking the already-active tab copies its path (`onTabClick`, `:7914`); "copy path" is scattered across header, active tab, tab right-click, editor right-click, vim menu.
- Emoji 🎙 in `tabFooterText` (`:8561`) inside an otherwise emoji-free themed UI.
- `sectionTitle = "Notes"` / `pinnedTitle = "Pinned"` hard-coded, against "config over code".
- `DismissedNotes` is a global static keyed on absolute paths, not scoped per `[notes]` section.
- `[notes] font = "Hack Nerd Font Mono"`, `font-size = 16` diverge from DESIGN.md's editor spec (SF Mono, 13 pt) — a legit override, but docs and shipped default disagree.
- Native mode has no find-bar empty placeholder and no "N matches" affordance beyond `findCountLabel`.

## Questions to Consider

1. If notes is the app's namesake, why is **files** the default view and notes has no hotkey — is notes the product, or just the first feature?
2. Should one markdown file render as raw text, rendered markdown, *and* a serif reading page, or is that three products competing for one tab?
3. If "notes" accepts PDFs, RTFs, `.cfg` and `.log`, is it a notes editor or a general file viewer wearing a notes hat?
4. What exactly does the user lose when they close a tab, and why is that the one destructive action with no confirmation or undo?
5. Is a raw-markdown `NSTextView` worth keeping when both vim and Prose render markdown properly?
