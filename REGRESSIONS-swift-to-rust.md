### A-09 — Copy / Cut / Paste files; move-vs-copy decision (main popup/notes/files window (first half))

- **Swift did:** Cmd+C/X put each path on the general pasteboard as a fileURL plus a plain-string path; the status explains '⌘V pastes the file, or its path as text'; Paste copies, but moves only if the clipboard is still the one that was cut (tracked by pasteboard changeCount).
- **Reader says Rust:** `differs` — The pasteboard format matches (NSPasteboardItem with fileURL + string). - **Rust refs (reader):** `app/host.rs:10198-10225`, `app/host.rs:10179-10193`, `app/host.rs:8360-8383`
- **Validator (confirmed):** Confirmed: after an unrelated clipboard change the stale FILES_CUT bool still forces a move; Swift's changeCount guards this. Toast wording also differs.
  - Swift check: 5459-5476 copyFiles writes one NSPasteboardItem per path (fileURL + string), sets Self.cutChange = pb.changeCount on cut; 5478-5493 pasteFiles move = forceMove || Self.cutChange == NSPasteboard.general.changeCount; 5363 cutChange; 5378-5381 clipboardFiles.
  - Rust search: host.rs:10198-10221 pasteboard format matches (NSPasteboardItem fileURL+string).
